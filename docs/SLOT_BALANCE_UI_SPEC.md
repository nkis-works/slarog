## 2. モード

### 差枚から見る

対象範囲、G数、差枚を入力する。G数と差枚へ同じscopeを適用する。差枚ベース出玉率、3枚掛け換算IN／OUT、1,000Gあたり差枚を表示し、換算OUTが負数なら率を表示しない。

### 投資・回収を見る

現金投資額、現在枚数、交換条件、交換単位を基本欄とし、貯メダル、交換済み金額、貸出条件、G数、差枚をdetails内へ分離する。交換条件・単位に初期値を入れない。現金0円では現金回収率を非表示、貯メダル0枚では重複回収ラインを表示しない。

### 区間・IN/OUT

- 区間差枚: 1〜100件、追加、削除、Undo、順序維持、各区間と合計を表示。
- 実IN/OUT: 合計入力と区間入力を切替。実IN 1以上、実OUT 0以上。
- 通常時コイン持ち: 正味使用枚数の直接入力と内訳入力を切替。2つの確認checkboxを初期uncheckedとする。

## 3. 状態

差枚、投資、区間、実IN/OUT、コイン持ちに独立した`currentInputRevision`と`calculatedInputRevision`を持つ。入力イベントごとにrevisionを更新し、計算済みrevisionと異なればstaleとする。staleの旧結果は残せるが、明示bannerと低い視覚強度で再計算を要求する。

モード切替は入力を破棄せず計算を実行しない。結果領域も現在の計算種別だけを表示する。

## 4. 表示契約

結果値は`ValueProvenance`から入力／計算／概算／参考／実測ラベルを決める。正数は`+`、負数は`-`、0は符号なし、単位は必須とする。

errorはfield付近とfocus可能な概要へ表示し計算を止める。warningは結果と併記し、infoは静かな補足とする。同じmessage codeは一覧で重複させない。

## 5. URLと通信

全リンクは`../../`または同階層の相対URLを使用する。入力をURLへ付加せず、storage、Cookie、API、広告、analyticsを使用しない。Slarog CTAは`../../index.html`への通常リンクだけとする。

## 6. 公式サイト導線

公式トップはスラログを主役に保ち、desktop／mobile navigationと主要説明を妨げないコンパクトなカードからスロバランスへ遷移できる。supportからも到達でき、root各ページの共通navigation／footerは相対URLで整合させる。404本文へ目立つ追加カードは置かない。

## 7. レスポンシブとアクセシビリティ

320px以上で横overflowを発生させず、計算式は画像化しない。FAQは`details`を利用して長い縦表示を抑え、キーボードで操作できる。mobile／desktopで入力、結果、Slarog CTA、広告差込位置、計算式、FAQの順序を維持する。
