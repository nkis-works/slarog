# 機能マスター

## 分類

- **MVP**: 名称変更と同時に公開品質まで実装する。
- **Next**: ドメイン契約はMVPで定義し、次の小リリースでUI提供する。
- **Future**: 利用者検証後に再判断する。
- **Do not build**: 原則とプライバシー境界に反するため作らない。

## MVP受け入れ条件

### クイック分析

- 空の状態では結果を出さず、例 `4,000` と `+500` を示す。
- 全角数字、全角符号、カンマ、周辺空白を正規化する。
- 総Gは1以上の整数。差枚は整数で、想定OUTが負になる値はerror。
- 4,000G/+500枚の代表期待値を既存契約と一致させる。
- Enterで計算し、結果見出しへフォーカスを移す。
- 入力値をURL、storage、cookie、console、外部通信へ出さない。

### 基準比較

- 常に100/103/105%の3行を同じ順で表示。
- 各行に基準の期待差枚、実績との差、単位、符号を表示。
- 色に加え「上回る/下回る/同じ」をテキスト表示。
- 初期は主判定を出さず、比較行を選択したときだけ1文要約。
- 選択はページリロードで失われ、保存しない。

### 結果表示

- 初期結果ブロックは3つ以内。
- 実績率を最上位、換算値と想定IN/OUTを次に置く。
- 高精度内部値と表示丸めを分離。
- 画面読み上げは結果更新を一度だけ通知。

## Next受け入れ条件

### 目標逆算

- 目標Gは現在Gより大きい。
- 目標率は正数で、計算可能な有限値。
- 「必要差枚」は残区間で必要な正味差枚であり、保証ではないと明示。
- 必要区間OUTが負になる目標は「入力上成立しない」とする。

### 区間

- 直接入力と累積地点入力を明確なタブで分離。
- 累積Gは厳密増加。累積地点の差分を区間値へ変換してから同一エンジンへ渡す。
- 少なくとも2区間、最大20区間を推奨。
- 各区間の基準差、全体への寄与、最大下落、最大回復を定義どおり表示。
- 行削除後もラベル番号、エラー関連付け、フォーカスが破綻しない。

## 優先順位の理由

クイック分析は現行資産を最も安全に再利用でき、競合と同等の入力速度に説明可能性を加えられる。目標逆算と区間寄与は差別化が大きいが、用語誤認と数式検証が必要なためNext。投資・回収は有用だが、クイック導線を邪魔しない段階開示として後置する。
