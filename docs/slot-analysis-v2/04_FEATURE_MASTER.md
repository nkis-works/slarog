# 機能マスター

## 分類

- **Release Core**: 新UIを本番へ切り替えるまでに、公開品質で全項目を完成させる。開発PRの分割は可能。
- **Later**: Release Core公開後、利用者検証と安全性評価を経て再判断する。
- **Do not build**: 中立性、プライバシー、運用単純性に反するため作らない。

## Later

- 仮想の将来シナリオと持ち越し期待値。
- 時給換算と複数候補比較。
- CSV入出力、印刷表示、結果画像。
- Release Core後の利用者検証で必要性とプライバシー境界を確認したその他の補助機能。

## Do not build

- 機種DB、機種固有値の自動更新、設定推測。
- 履歴保存、共有URL、アカウント同期。
- 有利/不利、勝ち/負け、継続/終了などの判断。
- Auto Adsまたは入力/結果途中へ割り込む広告。
- 入力値や計算結果を含むAnalytics・イベント送信。

## Release Core受け入れ条件

### クイック分析と基準比較

- 空の状態では結果を出さず、例 `4,000` と `+500` を示す。
- 全角数字、全角符号、カンマ、周辺空白を正規化する。
- 総Gは1以上の整数。差枚は整数で、想定OUTが負になる値はerror。
- 4,000G/+500枚で実績率104.2%、+125枚/1,000G、想定IN12,000枚、想定OUT12,500枚となる。
- 初期結果は実績出玉率、総G/差枚、1,000Gあたり差枚の順。想定IN/OUTは「計算条件を見る」の中だけに置く。
- Enterで計算し、結果見出しへフォーカスを移す。
- 入力値をURL、storage、cookie、console、外部通信へ出さない。
- 100/103/105%を常に同じ順で表示するが、初期選択は置かない。
- 選択前は各行の事実として「上回る/下回る/基準通り」だけを示す。
- 選択後だけ、その基準に対する要約を表示する。
- 厳密差が0なら「基準通り」。表示が0枚でも厳密差が非0なら「差は1枚未満（上回る/下回る）」とする。

### 目標逆算

- 目標Gは現在Gより大きく、目標率は正の有限小数。
- 残区間の整数境界を切り上げ、境界値で再計算した必要残区間率を表示する。
- 正なら `あと+N枚必要`、0なら `差枚0枚以上で目標に到達`、負なら `−N枚までなら目標を維持`。
- 必要残区間OUTが負なら、実行可能境界を0%へ丸め、`any_nonnegative_out_suffices` として扱う。
- 数学的な境界であり、将来結果、期待値、推奨ではないと明示する。

### 区間分析

- 直接区間と累積地点を明確なタブで分離する。
- 累積Gは厳密増加。任意の開始地点から差分へ変換し、直接区間と同じ計算へ渡す。
- 本番UIは最大10区間。累積地点の初期UI候補は開始点を含む11地点。ドメイン層は100区間まで安全に処理する。
- 区間基準の初期選択はなし。未選択時は関係、判定、寄与を返さない。
- 選択後だけ `103%基準：好調区間／低調区間` のような区間ラベルと寄与を表示する。
- 区間率を単純平均せず、合計G/差枚から加重された合計率を求める。
- 寄与の厳密合計が合計の基準差と一致する。
- 入力地点間の最大下落と下落後の最大回復は、元地点indexを保持して表示する。

## 公開ゲート

RC-01〜RC-16の全項目、アクセシビリティ、レスポンシブ、既存回帰、プライバシー境界がすべて合格するまで新UIを本番へ切り替えない。ドメイン、UI、移行は積み上げPRで分割できる。
