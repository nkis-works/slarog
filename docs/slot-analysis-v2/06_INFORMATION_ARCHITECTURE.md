## 並び順の理由

入力と結果を最短距離に置き、自社CTAを広告より先にする。高度な機能は結果を得た利用者が明示的に開く。式・FAQは信頼性に必要だが、初回タスクを遮らない下層に置く。

## 画面状態

| 状態       | 表示                          | フォーカス/通知                 |
| ---------- | ----------------------------- | ------------------------------- |
| 初期       | 2入力、例、詳細機能の短い予告 | H1から自然順                    |
| 入力中     | 値、必要時の近傍エラー        | 勝手に移動しない                |
| エラー     | 要約＋各フィールド説明        | 最初の不正フィールド            |
| 結果       | 3結果＋比較リスト             | 結果見出しへ移動、polite通知1回 |
| 基準選択   | 選択行＋中立要約              | 選択ボタンに留める              |
| 詳細を開く | 対象フォーム                  | 見出しへ移動                    |
| 再計算     | 同じ結果領域更新              | 不要なスクロールを抑える        |
| リセット   | 初期へ戻る                    | 総ゲーム数へ                    |

## 段階開示ルール

- `<details>`を使うのは説明・FAQ。フォーム機能はボタン＋`hidden`で状態を明示する。
- 詳細機能は同時に1つだけ開く。未送信値がある状態で別機能を開く場合は値を保持するが保存はしない。
- クイック値を目標逆算/投資へ「この画面内で使う」操作は許容する。暗黙コピーはしない。
- 区間とクイックの合計が一致しても自動同期しない。利用者が採用操作をする。

## ナビゲーション

- グローバルナビのラベルは `スロット出玉分析`。
- ページ内目次は結果後に `詳細分析 / 計算式 / 使い方 / FAQ` の4リンク。
- 戻る操作で入力状態の復元を保証しない。履歴APIを操作しない。
- hashに入力値を入れない。ページ内anchorは固定文字列のみ。

## URL移行案（実装フェーズ）

1. 新URL `/tools/slot-analysis/` を公開。
2. canonical、sitemap、サイト内リンクを新URLに統一。
3. 旧 `/tools/slot-balance/` を301/308で新URLへ恒久転送。
4. query/hashは入力に使わず、転送で利用者値を引き継がない。
5. source/dist E2Eで新旧URLとpreview noindexを検証。

本フェーズでは一切実施しない。

## SEO情報設計

- titleとH1は機能名を先頭にする。
- descriptionは「総ゲーム数と差枚から実績出玉率、基準差、区間、目標逆算を計算。無料・登録不要。」の範囲。
- 機種名や設定判別語を量産しない。
- FAQ構造化データは、画面上のFAQと完全一致しGoogleの現行要件を再確認できる場合だけ。
- preview/pages.devはnoindexを維持。
