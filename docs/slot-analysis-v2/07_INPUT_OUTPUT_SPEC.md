# 入出力仕様

## 共通入力規則

- テキスト入力を使用し、`inputmode="numeric"` または `decimal` を指定する。
- NFKC正規化後、外側空白と桁区切りカンマを除く。
- `＋/−/－` をASCII `+/-` に正規化する。
- 指数表記、単位付き文字列、式、無限値を受け付けない。
- placeholderはラベル代わりにしない。
- 表示例は入力欄外に置く。
- 入力値をHTML、URL、ログ、storage、外部リクエストへ反映しない。

## クイック入力

| ID            | ラベル     | 型/範囲                       | 必須 | 例    | エラー            |
| ------------- | ---------- | ----------------------------- | ---- | ----- | ----------------- |
| `quick-games` | 総ゲーム数 | 整数、1〜9,999,999            | 必須 | 4,000 | 1以上の整数で入力 |
| `quick-net`   | 差枚       | 整数、−29,999,997〜29,999,997 | 必須 | +500  | 整数で入力        |

追加制約: `G×3 + N >= 0`。上限はUI/性能保護であり遊技上限を意味しない。

## クイック出力

|   順 | ID              | ラベル           | 表示       | 例                | 補助                               |
| ---: | --------------- | ---------------- | ---------- | ----------------- | ---------------------------------- |
|    1 | `actual-rate`   | 実績出玉率       | 小数1桁%   | 104.2%            | 主結果                             |
|    2 | `input-summary` | 総G / 差枚       | 整数2値    | 4,000G / +500枚   | 入力の再確認                       |
|    3 | `per-1000`      | 1,000Gあたり差枚 | 符号付き枚 | +125枚            | 比較用換算                         |
| 詳細 | `assumed-flow`  | 想定IN / OUT     | 整数枚2値  | 12,000 / 12,500枚 | 「計算条件を見る」内、実測ではない |
| 詳細 | `sensitivity`   | 100枚変化の感度  | 小数1桁pt  | 約0.8pt           | 「計算条件を見る」内               |

初期結果は上表の1〜3を順に表示する。想定IN/OUTを独立した結果カードにしない。

## 基準比較出力

各行のデータ:

```ts
type BenchmarkRow = {
  rateBasisPoints: 10000 | 10300 | 10500;
  expectedNetMedals: Rational;
  differenceMedals: Rational;
  relation: 'above' | 'equal' | 'below';
};
```

`relation`は丸め前の厳密値で決める。厳密差0だけが`equal`で表示は`基準通り`。整数表示が0枚でも厳密差が非0なら `差は1枚未満（上回る）` または `差は1枚未満（下回る）` と表示する。クイック比較は初期選択なし。

## 目標逆算入力

| ID                     | ラベル     | 型/範囲               | 初期値/例 | 制約            |
| ---------------------- | ---------- | --------------------- | --------- | --------------- |
| `target-current-games` | 現在の総G  | quickから明示コピー可 | 4,000     | 1以上           |
| `target-current-net`   | 現在の差枚 | 整数                  | +500      | OUT非負         |
| `target-total-games`   | 目標総G    | 整数                  | 5,000     | 現在Gより大きい |
| `target-rate`          | 目標出玉率 | 0.1〜999.9%           | 100.0     | 正数            |

出力: 残りG、残区間の厳密必要差枚、切り上げた整数境界、許容減少枚数、整数境界から再計算した残区間率、状態code、前提。

- 正: `あと+N枚必要` (`must_gain`)
- 0: `差枚0枚以上で目標に到達` (`no_net_change_required`)
- 負: `−N枚までなら目標を維持` (`can_lose_up_to`)
- 必要OUTが負: 実行可能境界を0%へclampし `any_nonnegative_out_suffices`

## 区間入力

### 区間直接

各行:

| 項目     | 型                     | 制約                           |
| -------- | ---------------------- | ------------------------------ |
| 区間名   | 任意テキスト最大20文字 | 表示のみ、HTMLとして解釈しない |
| 区間G    | 整数                   | 1以上                          |
| 区間差枚 | 整数                   | 区間OUT非負                    |

本番UIは2〜10行、ドメイン層は最大100行。追加時は新しい区間名へフォーカス。削除時は直前の「削除」または「区間追加」へフォーカス。

### 累積地点

各行: 地点名、累積G、累積差枚。開始点は0/0に限定しない。本番UIの初期候補は開始点を含め2〜11地点、ドメイン層は区間換算後100区間まで。累積Gは厳密増加し、差枚は増減可能。隣接差分が区間OUT<0になる場合はerror。

### 区間出力

- 合計G、合計差枚、合計実績率。
- 各区間G/差枚/率。
- 基準が選択された場合だけ、基準との差、`好調区間/低調区間`、押し上げ/押し下げ。未選択なら関係、判定、寄与は出力しない。
- 入力地点間の最大下落、下落後の最大回復。
- 直接入力か累積変換かのprovenance。

## 投資・回収入力

### 簡易

| 項目       | 型/単位       | 必須 |
| ---------- | ------------- | ---- |
| 現金投資   | 0以上の整数円 | 必須 |
| 現在メダル | 0以上の整数枚 | 必須 |
| 交換率     | 正数 円/枚    | 必須 |
| 交換単位   | 1以上の整数枚 | 必須 |

### 詳細（段階開示）

貯メダル、交換済み円、貸出率、今回のG/差枚。初期画面では表示しない。簡易結果は交換額、現金収支、現金回収率、端数。詳細結果は貯メダル価値と総回収率を分離。

## 表示フォーマット

- 日本語ロケールの桁区切り。
- 正値差枚は `+`、負値はUnicode minusではなく見分けやすい `−` を表示。
- 単位を数値と同じテキストノードまたは読み上げ可能な隣接要素に置く。
- `%`とpercentage pointを混同せず、比較差は `ポイント`。
- `0` は `±0` ではなく `0`。
- 未計算は `—`、計算不能は説明付きエラー。`NaN`/`Infinity`をDOMへ出さない。

## 状態・データ寿命

- JavaScriptメモリ内だけ。
- reload/離脱で消える。
- localStorage、sessionStorage、IndexedDB、Cookie、Cache Storageを使用しない。
- query/hash/history stateに値を入れない。
- clipboard、share API、downloadはRelease Coreに含めない。

## エラー文例

- `総ゲーム数は1以上の整数で入力してください。`
- `差枚が小さすぎるため、想定OUTが0枚未満になります。`
- `目標総ゲーム数は現在の総ゲーム数より大きくしてください。`
- `地点3の累積ゲーム数は、地点2より大きくしてください。`
- `区間2はこの入力ではOUTが0枚未満になります。`

利用者を責める表現、英語例外、コード番号だけの表示を避ける。
