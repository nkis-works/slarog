# スロット出玉分析 v2 — Executive Summary

- 文書版: 1.0
- 調査基準日: 2026-07-18
- 対象: NKIS Works 公式サイト内の現行「スロバランス」
- フェーズ: 設計・検証用プロトタイプのみ（本番未変更）

## 結論

現行ツールの信頼できる計算基盤は残し、最初の20秒で価値が伝わる「2項目入力 → 3つの主要結果」を中心に全面再設計する。機種名、設定、ホール、ユーザー履歴を必要としない、過去実績を扱う汎用ツールとする。

推奨名称は **スロット出玉分析**、推奨URLは `/tools/slot-analysis/`。名称は機能を直接説明し、未来予測や設定判別を約束しない。現行 `/tools/slot-balance/` は実装フェーズで恒久転送候補とするが、本フェーズではURLもリダイレクトも変更しない。

## 提案する体験

1. 総ゲーム数と差枚だけを入力する。
2. 実績出玉率、1,000Gあたり差枚、想定IN/OUTを即時表示する。
3. 100%・103%・105%の基準差を縦並びで比較する。
4. 必要な人だけが「目標逆算」「区間分析」「投資・回収」を開く。
5. 結果の直後にスラログ導線を出し、その後に将来の手動広告1枠を置く。
6. 計算式、使い方、FAQ、免責を下層に置く。

## 採用判断

| 論点       | 採用                     | 理由                                      |
| ---------- | ------------------------ | ----------------------------------------- |
| 初期入力   | 総ゲーム数、差枚の2項目  | 最短で実績の要約に到達できる              |
| 初期結果   | 最大3ブロック            | 認知負荷を抑え、重要数値を見失わない      |
| 基準比較   | 100/103/105%を縦リスト   | 横スクロールを避け、読み上げ順も自然      |
| 主判定     | 初期は中立               | 任意基準を「正解」と誤認させない          |
| 機種DB     | 非採用                   | 更新負担、誤情報、設定推測を避ける        |
| 保存・共有 | 非採用                   | URL漏えい、端末残存、同意管理を増やさない |
| 広告       | 将来、CTA後に手動1枠のみ | 入力・結果を遮らず収益化余地を確保        |
| UI方式     | 単一ページ＋段階開示     | 現行の静的ビルドと継続運用に合う          |

## 成功条件

- 4000G・+500枚で `104.2%`、`+125枚/1,000G`、想定IN `12,000枚`、想定OUT `12,500枚`。
- 20秒以内に初回結果へ到達できる。
- 320/390/430/768/1440pxで横はみ出しがない。
- 200%ズーム、キーボード操作、スクリーンリーダーの読み順が成立する。
- console、pageerror、外部通信、Cookie、localStorage、sessionStorage、IndexedDBが0。
- axe critical/seriousが0。
- 設計物とプロトタイプが本番 `dist` に混入しない。
