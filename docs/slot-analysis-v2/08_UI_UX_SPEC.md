# UI / UX仕様

## デザイン方向

既存NKIS Worksサイトの明るい背景、青系アクセント、角丸カード、十分な余白を継承する。プロトタイプは新規ブランドを作らず、情報階層と操作検証を目的とする。

## レイアウト

### モバイル（320〜767px）

- 1カラム、左右16px（320pxでは12pxまで縮小可）。
- 入力、ボタン、結果は100%幅。
- 結果値は長い単位でも折返し可能。
- 比較は縦リスト。横スクロールを必須にしない。
- sticky CTA、固定広告、画面下固定ナビは使わない。
- 390×844pxの初期viewport（設計プロトタイプの説明bannerを除く）に、H1、一文説明、2入力、`出玉率を見る`ボタンを収める。信頼/機能一覧でフォームを押し下げない。

### タブレット（768〜1023px）

- 本文最大760px。
- クイック入力は2列も可。ただしDOM順は総G→差枚→計算。
- 詳細結果は2列、比較は縦リスト。

### デスクトップ（1024px以上）

- 全体最大1120px。
- クイック入力と説明を5:4、結果は主結果と比較を7:5で配置可能。
- 読み順はDOMで入力→結果→詳細を維持。
- 1440pxでも1行を長くしすぎない（本文70ch程度）。

## コンポーネント

### ヒーロー

- eyebrow: `無料・登録不要・端末内で計算`
- H1: `スロット出玉分析`
- lead: `総ゲーム数と差枚から、実績出玉率と基準との差を確認できます。`
- 免責はヒーローで長文にせず `未来の結果や設定を予測するものではありません。`

### クイックフォーム

- 2つの常時表示ラベル。
- 符号例を差枚の補助文にする。
- primary `出玉率を見る`、secondary text `入力をリセット`。
- 自動計算ではなく明示submit。入力中の数値変動で画面が揺れない。

### 結果

- `あなたの入力結果`ではなく `この入力の実績`。
- 実績率を最大の数字として最上部。
- 実績出玉率、入力した総G/差枚、`1,000Gあたり`の順。想定IN/OUTは独立カードにせず、`計算条件を見る`内へ置く。
- 100/103/105比較はボタンを含むリスト。初期選択なし。
- 1文要約は選択後だけ表示: `この入力は103%基準の差枚を140枚上回ります。`
- 表示0枚でも厳密差が非0なら `差は1枚未満（上回る/下回る）`。厳密差0だけを`基準通り`とする。

### 詳細機能ランチャー

3カード: `目標から逆算`、`区間を比べる`、`投資・回収を計算`。

- それぞれ「何が分かるか」を1文で示す。
- 押すまでフォームをDOMで非表示にする。
- `上級者向け`ではなく目的語で説明する。
- 区間の比較基準は初期選択なし。選択後だけ `103%基準：好調区間／低調区間` と寄与を示す。

### 投資・回収

- 基本入力は`現金投資`、`現在メダル`、`1,000円分への交換に必要な枚数`の3項目だけを表示する。
- 交換条件の例は`50枚 / 1,000円`、`56枚 / 1,000円`とし、`円/枚`を主入力にしない。
- 交換単位、貯メダル使用枚数、交換済み円、貸出枚数/1,000円、今回のG/差枚はdetails内へ置く。
- 簡易結果は交換額見込み、現金収支、回収率を先に表示し、端数や内訳は詳細へ分離する。

### 計算条件

- `計算条件を見る`はdomain成功結果の`metadata`をUI adapterで日本語へ変換して表示する。
- rendererは表示値から式、前提、丸め、warningを再計算・推測しない。
- domain codeを日本語表示へ対応付ける表はUI層に閉じ、未知codeは安全な汎用説明として扱う。

### スラログCTA

- 見出し: `遊技記録を続けて残すならスラログ`
- 本文: 手入力の記録・グラフなど、実装済み事実だけ。
- 広告ラベルと外観を分ける。
- 外部遷移なら視覚・読み上げで示す。

### 将来広告

- CTAの後、計算式の前。
- 初期リリースではDOMも空白も作らない。
- プロトタイプは破線枠で `将来の手動広告位置（設計確認のみ）` と明示。
- 有効時も1枠、レスポンシブdisplayのみ。詳細は [12_AD_MONETIZATION_SPEC.md](./12_AD_MONETIZATION_SPEC.md)。

## 結果レール vs 縦リスト

| 観点           | 横レール                 | 縦リスト         |
| -------------- | ------------------------ | ---------------- |
| モバイル一覧性 | 隠れた項目が発生         | 3件すべて見える  |
| 200%ズーム     | 横操作が増える           | 自然に縦へ流れる |
| 読み上げ       | 視覚位置とずれる恐れ     | DOM順と一致      |
| デスクトップ   | コンパクト               | やや縦長         |
| 選択操作       | カードとして分かりやすい | 行ボタンで十分   |

**推奨: 縦リストを正式UI**。デスクトップでも同じDOMを用い、密度だけ調整する。横レールは比較用プロトタイプに残すが採用しない。

## アクセシビリティ

- HTML landmark、見出しレベル、`form/fieldset/legend`を使用。
- 44×44px以上の主要タップ領域。
- `:focus-visible`を2px以上、背景と3:1以上。
- 通常文字4.5:1、大文字/大テキスト3:1以上。
- 正負は色＋符号＋語句で表す。
- エラーは `aria-describedby`、要約はリンクでフィールドへ。
- 結果領域は `role=status`の乱用を避け、短い更新文だけ`aria-live=polite`。
- 計算後のフォーカス移動はsubmit時のみ。入力中は移動しない。
- `prefers-reduced-motion`で移動/フェードを無効化。
- 200%/400%文字拡大で情報欠落がない。

## 文言規約

- ボタンは動詞＋目的語: `出玉率を見る`、`区間を追加`。
- `機械割`は検索補助・説明に留め、主語は`実績出玉率`。
- `おすすめ設定`、`勝てる`、`期待できる`を使わない。
- 数学上の条件は `必要`、不確実性は `予測ではありません`。
- エラーで `不正`、`失敗`、`間違い`を避ける。

## モーション

- 結果表示は150ms以下のopacityのみ、reduce時は0。
- accordionの高さアニメーションは行わない。
- 数字のカウントアップは読み間違いを招くため使わない。
- トーストは使わず、操作箇所の近くに状態を置く。
