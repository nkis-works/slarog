# プロダクト定義

## 一文定義

スロット出玉分析は、総ゲーム数と差枚を起点に、過去の実績出玉率、基準との差、区間ごとの寄与、目標時点までの必要差枚を、機種情報なしで説明する無料Webツールである。

## 解決する課題

- 差枚だけでは、回したゲーム数に対してどの程度の実績だったか分からない。
- 出玉率だけでは、100/103/105%との差が何枚か直感的に分からない。
- 区間の合計だけでは、どの区間が全体を押し上げ/押し下げたか分からない。
- 目標総ゲーム数までに、あと何枚・何%の区間実績が必要か手計算しづらい。
- 既存ツールには機種DB、設定推測、収支履歴、広告SDKなどが混在しやすい。

## 対象利用者

### 主対象

- 遊技後または途中に、総Gと差枚から実績を短時間で確認したい人。
- データ表示機やメモから区間値を読み取り、寄与を比べたい人。
- アプリ登録や機種選択なしで、ブラウザだけで計算したい人。

### 副対象

- 交換率や投資回収を必要なときだけ確認したい人。
- 計算根拠を確認し、自分で再計算したい人。
- スラログで詳細な遊技記録を残す前に、単発の数値を確認したい人。

## 対象外

- 設定判別、勝敗予測、台選び、立ち回り推奨。
- 機種固有の公称値、天井、ゾーン、モード、終了画面。
- 店舗や台の優劣ランキング。
- 期待収支・期待時給を未来の利益として保証すること。
- アカウント、クラウド同期、履歴、共有リンク。
- 画像OCR、データカウンター連携、スラログへの自動転送。

## プロダクト原則

1. **最短入力**: 初期画面は総ゲーム数と差枚だけ。
2. **過去形で表す**: 「この入力の実績」「基準との差」と表現する。
3. **想定と実測を分ける**: 3枚/GのINは「想定IN」と明記する。
4. **中立比較**: 基準を設定示唆や正解として扱わない。
5. **段階開示**: 高度な計算は結果後の明示操作で開く。
6. **説明可能**: 数値に単位、式、丸め、前提を結び付ける。
7. **端末内完結**: 保存、URL埋め込み、外部送信を行わない。
8. **アクセシビリティ優先**: 色だけ、横スクロールだけで意味を伝えない。
9. **運用単純性**: 静的配信と既存ビルドに適合し、機種更新を不要にする。
10. **広告は従属**: 結果とスラログCTAを完了した後に手動1枠だけ。

## ジョブストーリー

- 総Gと差枚が分かったとき、実績率と1,000G換算を知り、規模の違う実績を比較したい。
- 103%など任意基準を置くとき、基準に対して何枚上/下か知り、断定語なしで解釈したい。
- 複数区間を入力するとき、合計だけでなく各区間の寄与を知り、全体の変化を説明したい。
- 目標総Gを置くとき、残り区間で必要な差枚と区間出玉率を知り、数学的な到達条件を確認したい。
- 現金・持ちメダルを入力するとき、交換単位と端数を含む回収結果を知りたい。

## MVP成功指標

解析・Cookieを入れないため、初期は自動収集KPIを設定しない。公開前の測定可能な品質指標を採用する。

- 代表参加者の80%以上が、説明なしで20秒以内にクイック結果へ到達。
- 結果確認後、参加者の80%以上が「過去実績であり予測ではない」と説明できる。
- 区間入力で累積/区間差枚の混同が0。
- 320pxと200%ズームでタスク完了率100%。
- WCAG 2.2 AA相当の主要項目、axe critical/serious 0。
- 既存83 unit、22 source E2E、14 dist E2Eが継続成功。
