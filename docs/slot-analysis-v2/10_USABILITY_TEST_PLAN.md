# ユーザビリティテスト計画

## 目的

計算の正しさだけでなく、20秒以内の理解、過去実績と予測の区別、区間入力方式、基準比較UI、モバイル/ズーム/キーボード操作を検証する。

## 参加者

- 6〜8名。
- スロット経験: 初心者2、中程度3、頻繁2以上。
- 計算ツール経験: 未経験を最低2名。
- iPhone/Android利用者を混在。
- 可能ならキーボードのみ利用者1名、画面拡大利用者1名。

## 環境

- 本番ではなくローカル非公開プロトタイプ。
- 390px相当スマートフォンを主、1440pxデスクトップを副。
- 320/430/768pxと200%ズームをモデレータ検証。
- 入力・画面録画は参加者同意がある場合のみ。実際の遊技履歴や個人情報は使わずテスト値を渡す。

## タスク

### T1 クイック計算

「4,000Gで差枚が+500枚でした。実績を確認してください。」

期待:

- 20秒以内に計算。
- 104.2%、+125枚/1,000G、IN12,000、OUT12,500を見つける。
- 入力が保存・送信されないことを必要時に確認できる。

### T2 基準比較

「103%を基準にすると、何枚上回る/下回るか説明してください。」

期待: +140枚上回ると回答し、設定103%や未来予測とは言わない。

### T3 目標逆算

「同じ状態から5,000G時点で100%を境界にした場合、残り区間の条件を確認してください。」

期待: 残り1,000G、−500枚以上、83.3%以上。`−500`の意味を説明できる。

### T4 区間直接入力

区間1: 1,000G/+200枚、区間2: 2,000G/−400枚、基準103%。

期待: 合計3,000G/−200枚/97.8%、寄与+110/−580、最大下落400を確認。

### T5 累積地点入力

地点0: 0/0、地点1: 1,000/+200、地点2: 3,000/−200。

期待: T4と同じ区間へ変換される。累積値を区間値として二重加算しない。

### T6 投資・回収

投資20,000円、現在1,200枚、20円/枚、1枚単位。

期待: 24,000円、+4,000円、120.0%。詳細入力を不用意に開かない。

### T7 説明・免責

「104.2%なら今後も勝てると言えますか？」

期待: 過去入力の実績であり、将来、設定、機種性能を予測しないと回答。

## 比較テスト

同じ参加者へ順序を入れ替え、結果比較をA:横レール、B:縦リストで提示する。

測定:

- 3基準すべての発見率。
- 103%差の回答時間と誤答。
- スクロール/スワイプ見落とし。
- 200%ズーム時の操作完了。
- 主観評価（分かりやすさ1〜5）。

採用基準: 誤答が少ない方を優先。同等なら縦リスト（アクセシビリティと実装単純性）を採用。

## 観察項目

- 最初にどこをタップするか。
- `差枚`の符号と単位の理解。
- `実績出玉率`と公称機械割の混同。
- `想定IN/OUT`の「想定」認識。
- 基準選択を設定選択と誤認しないか。
- `必要差枚 −500枚以上`の理解。
- 区間/累積タブの選び方。
- CTAと広告枠を識別できるか。
- 式/FAQへ迷わず到達できるか。

## 技術QA

- viewport: 320, 390, 430, 768, 1440。
- 200%ズーム。
- axe critical/serious 0。
- console/pageerror 0。
- 外部originへのrequest 0。
- Cookie/localStorage/sessionStorage/IndexedDB 0。
- URL query/hashへの入力値混入0。
- 主要操作のTab/Shift+Tab/Enter/Space/Escape。
- reduced motion、high contrast相当、長い日本語/大きな数値。

## 問題分類

- P0: 誤計算、入力漏えい、操作不能。
- P1: 主要結果の誤読、予測と誤認、横overflow、critical/serious a11y。
- P2: 迷い、説明不足、フォーカス不自然。
- P3: 文言・余白・軽微な視覚差。

P0/P1は実装開始前に設計修正。P2は根拠と対応期限を決める。P3はバックログ化できる。
